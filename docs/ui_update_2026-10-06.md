## 已实施

- 三章战斗与部署背景分别使用 `素材/背景/bg_act1.png`、`bg_act2.png`、`bg_act3.png`，置于深色底之上，默认透明度 0.32。
- 章节地图首次进入时显示 `icon_act1/2/3.png`：淡入、短暂停留、淡出；点击或确认键可跳过。开启“减少动画”时缩短渐变。同一局同一章在地图与节点间返回不重复播放。
- 初始角色显示“莫小洛”；初始卡组：拳击 1、攻击 2、冲锋 1、穷追 1、防御 5，共 10 张。稳定卡牌 ID 保留，只统一了显示名称和数量。
- 新战斗开场按 battle RNG 洗牌；继续存档不重新洗牌。更新前已经开始的战斗继续使用其已有牌序。
- 战利品三选一使用战斗同款卡框、图标、名称、费用与描述，可点击卡面或选择按钮；保留单独的放弃奖励按钮。
- 怪物血量、护盾、状态仅在点击怪物后的右侧详情显示；点击空地收起。怪物头顶保留行动意图，隐藏生命、护盾和状态条；点击身体也能选中。
- 尸鳖修正脚底锚点并隐藏原帧底部杂点，蜘蛛调整落点；加地面阴影。飞行敌人保留悬停。
- 三章 Boss 美术放大约 20%；第二章 Boss 另补偿原画身体占画布偏小的问题，在渲染时去掉白底，不改原 PNG。
- 回合/玩家行动提示缩为棋盘上方的小条，移除战斗中自动铺出的红色攻击范围色块。移动绿格、选中黄格、点选怪物后的紫色威胁格仍表示实际交互；部署红格仍标识敌人出生位置。
- HUD 接入生命、盾、牌组、金币、设置、返回素材。状态采用新素材，层数放右下角，超过一行自动换行；缺少新素材的状态使用旧图集回退。
- 商店只保留底部一个“离开”。
- 每章 Boss 胜利恢复已损失生命的 80%，向上取整且不超过最大生命，包括第三章最终 Boss。例：25/80 → 69/80；79/80 → 80/80。重复结算不会重复治疗或给奖励。
- 移除正式流程中的回环罗盘与相关回环叙述，暂不增加回溯。遗物稳定 ID 仅为旧存档兼容保留，停用其效果、掉落和图鉴展示。其余遗物继续生效。

旧存档的已有卡组不会被强制删成 10 张；开始新游戏才使用新初始配置。旧战斗此前已获得的资源不追溯扣除，停用遗物后不再触发后续奖励。

## 本轮新增或调整的接口

| 接口 | 用途 |
|---|---|
| `UIArt.texture(key)` / `UIArt.background(act_index)` | 集中加载新素材；按原图像素区域裁去透明留白，自动适配导入尺寸 |
| `BattleScreen.set_chapter(index)` | 切换本场战斗背景，正式流程由 RunFlow 注入章节 |
| `ChapterIntro.dismiss()` | 关闭章节浮现，不改变路线、战斗或 RNG |
| `NodeChoiceScreen.set_card_options(options)` | `card_id/index/data` 字典数组 → 可点击奖励卡面；选择经 `chose(data)` 交给原奖励规则 |
| `BattleHud.render_state(state, phase_text, selected_enemy_id)` | 只有合法且存活的选中敌人才显示右侧详情 |
| `UnitView.setup(id, is_player, appearance_key, visual_scale)` / `contains_pointer(global_position)` | 身体比例、落点与基于可见像素的点击判断 |
| `RelicDef.enabled` | 停用旧遗物而保留可解码 ID；装备、胜利钩子、宝箱、图鉴和恢复检查点共同过滤 |
| `CardSystem.shuffle_draw(deck, rng)` | 新战斗首次洗牌；从 EncounterBuilder 调用，恢复检查点不调用 |

素材原图没有覆写；背景导入最大边 2048，章节/生命图最大边 1024，其余 HUD/状态最大边 512。若换成不同画布尺寸的新图，需要同步 `presentation/common/ui_art.gd::REGIONS` 的原尺寸与裁切区域。

第二幕 Boss 采用 `presentation/battle/white_matte.gdshader` 临时清理原画白底；若未来换成真正透明背景的帧，可去掉 `UnitView` 对该外观的白色遮罩。该方案会同时透明化原图中的近白像素，新画应优先由美术提供干净 alpha。
