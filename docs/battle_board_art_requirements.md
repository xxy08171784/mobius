# 战斗棋盘地块美术规格（battle_board_art_requirements.md）

日期：2026-10-06。状态：**已冻结 v1**。承接 `directory_structure.md` §8 与棋盘等轴测原型 `iso_preview.gd`。
本文是**美术与代码的共同合同**：地块素材必须满足本规格，代码按本规格铺棋盘。改动需同步更新本文件。

> 决策记录：2026-10-06 选定 **1.5:1 俯视感**（备选 2:1 经典等轴，见 §7）。首批素材为 16 张 AI 生成地块（见 §6），已按本规格归一化。

## 1. 冻结规格（地块单格）

| 字段 | 值 | 说明 |
|---|---|---|
| **顶面菱形 W×H** | **300 × 200** | 邻格按此咬合；不可改（TILE_LAYOUT_DIAMOND_RIGHT 下 W/H 决定错位步长） |
| **画布 W×H** | **340 × 300** | 每格贴图统一尺寸；单一图集的前提 |
| **菱形中心锚点** | **(170, 120)** | 菱形在画布内的固定位置 |
| 菱形四角 | 顶 (170,20)、右 (320,120)、底 (170,220)、左 (20,120) | 由中心锚点推得 |
| **侧壁下延** | **80px** | 菱形底 y=220 → 画布底 y=300；决定"块"厚度与单位遮挡 |
| 安全边距 | ≥ 8px（实际左右 20、顶 20） | 内容不得贴画布边，防裁缺 |
| 明暗方向 | 全图一致（当前素材来自同一生成批次，已一致） | 光源不一致会闪 |

### 1.1 为什么这些数不能随便动
- 菱形 W/H 决定 Godot 等轴测网格的错位步长，所有格子按它对齐。
- 侧壁下延决定前后排叠压与 y-sort；太深 → 前排遮后排、单位被埋；太浅 → 块太扁没有厚度感。
- 锚点必须固定，否则单张图集内格子逐个漂移（首批素材 x0/y0 漂移正是问题所在）。

## 2. 归一化契约（算法）

对每张源图（首批 16 张，几何不齐，见 §6）：

1. **量菱形 bbox**（alpha 轮廓法，`tools/measure_tiles.gd`）：菱形宽 `W_d`、高 `H_d`、内容 bbox。
2. **各向异性缩放**：`sx = 300/W_d`、`sy = 200/H_d`，x/y **各自**缩放到目标，使菱形**精确**为 300×200。
   - 为何不是均匀缩放：这批 AI 图**每张透视不一致**（实测菱形高 188~214，差约 13%），均匀缩放只能内切、凑不出统一菱形，邻格必错位。故按轴修正。
   - 代价：各向拉伸实测 ≤ ~7%（如 x +3~4.5%、y 0~6.5%），地板纹理上可接受；脚本对 >10% 会告警，提示重新出图。
   - **若素材本身按 §1 规格出图**（几何一致），`sx = sy ≈ 1`，退化为无变形。
3. **底对齐**：缩放后菱形底边固定在 `y=220`（侧壁统一落在同一地面）。
4. **水平居中**：菱形中心固定在 `x=170` → 落入画布后菱形四角固定 (170,20)/(320,120)/(170,220)/(20,120)。
5. **裁入统一画布** 340×300。

输出 = 可直接进 TileSet 的格图。验收：所有格图菱形必为 300×200、锚点 x=20..319 / 顶 y=20。

> 注：**只对"几何不一致的存量素材"才用本归一化**。新出图按 §1 规格即天然一致，无需归一化，也就无拉伸。

## 3. 内容要求（新出图时遵守，可免归一化）

- 直接按冻结规格出图，边距 ≥8px。
- 顶面菱形**中心不贴边**；侧壁下延恰好 80px 或更浅（更浅也合法，统一即可；更深会被画布裁掉）。
- 单张图内光影方向一致；整批图之间光源方向一致。
- 地面类图可做**逐格 patchwork**（每格不同纹理，StS 风）；若要做无缝大地板，需另行设计可平铺规格，不在本文。

## 5. 接入代码（已落地 2026-10-06）

- **TileSet 运行时构建**：`presentation/battle/iso_board_theme.gd`（`IsoBoardTheme`）从 `assets/textures/tiles/act1/normalized/*.png` 生成并缓存 TileSet（`TILE_SHAPE_ISOMETRIC` + `TILE_LAYOUT_DIAMOND_RIGHT`，`tile_size=(300,200)`，`texture_region_size=(340,300)`），**不需要**编辑器手搭 `.tres`。纹理走 `load()` 读导入资源（导出安全），未导入时退回 `Image.load_from_file`。
- **对齐**：Godot 以 `map_to_local(cell)` 为中心绘制整张画布（340×300），而菱形中心在画布内为 `(170,120)`（比画布中心 `(170,150)` 高 30px），故菱形中心 = `map_to_local(cell) + IsoGrid.CENTER_OFFSET`，`CENTER_OFFSET = (0,-30)`（实测值）。cell ↔ 菱形中心／拾取的换算全部收口在 `presentation/battle/iso_grid.gd`（`IsoGrid`，纯函数、可无头测试 `tests/rules/test_iso_grid.gd`）。
- **棋盘视图**：`presentation/battle/board_view.gd` 由 GridContainer 占位改为 `Control` + `TileMapLayer`（地块）+ 高亮层 + `UnitView`（单位色块棋子，`presentation/battle/unit_view.gd`）。对外接口不变；另加 `render_deployment` 供 `app/run_flow.gd` 的进场选格屏复用。
- 输入拾取 `local_to_map` 语义对齐 `BoardState(col,row)`。

> 若目视发现单位/高亮相对地块整体纵向偏 ~30px，只需改 `IsoGrid.CENTER_OFFSET` 一个常量（备选 `(20,20)`，取决于居中基准取 region 还是 tile_size）。
